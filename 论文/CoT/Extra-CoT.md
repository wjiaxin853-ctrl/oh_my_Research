#### （a）CoT Compressor 语义压缩器

##### 一句话

教一个专门的压缩器，学会哪些 CoT 内容重要，进而生成语义保留的数据。

##### 阶段 (a) 的目的

为后续模型训练提供语义尽可能完整的压缩 CoT 数据，而不是直接训练最终的推理模型。

##### 翻译
Semantically-preserved, Question-aware CoT Compressor Training：语义保持、问题感知的思维链压缩器训练

##### W，F，Q，T含义
![[截屏2026-10-21 21.44.21.png]]

###### 第一步：为什么要同时区分 Word 和 Formula？
```
因为数学公式不能像普通文字一样随意拆开压缩。
举个例子：
原始推理：
> 首先我们计算 2x+3=11，两边减去3，得到 2x=8，所以 x=4 。
压缩器可以删除“首先我们计算”这样的词语，但应该完整保留关键数学公式。
所以论文设计了 Formula-aware Atomic Segmentation（公式感知的原子化分割）。
意思是：先把推理过程切分成有意义的单位，把数学公式当成不可随意拆开的整体。
```

##### 第二步：从 Word-level 转换到 Token-level

```
图中可以看到两个层次：
	- Word-level：词语和数学公式级别。
	- Token-level：语言模型实际处理的 Token 级别。
因为一个词或一个数学公式可能被分词器拆分成多个 Token。
```
![[截屏2026-10-21 22.11.33.png]]

##### 第三步：训练CoT Compressor

图中紫色的框，就是要训练的上下文压缩模型

输入包括数学问题 $q$ 和原始推理过程 $z$，输出是各 Token 的重要性分数。

$$
 s_i=\operatorname{Imp}_{\phi}(t_i\mid q,z) 
$$
含义：模型根据问题和整个推理上下文，判断第 $i$ 个 Token 有多重要

Question-aware（问题感知） 的含义就在这里：它不是孤立判断某个词是否重要，而是结合“当前究竟在解什么问题”来判断。

##### 第四步：图中最下面的 Masked Token Index 是什么？

```
图中的数字 `0、1、2、3` 不是正确率，也不是 Token 重要性分数。
它们表示原始标注单元与 Token 之间的对应索引。
例如，一个公式被分词器拆成多个 Token，这些 Token 仍然属于同一个公式单元，因此可以通过对应索引保持关联。
图中灰色 Token 表示被掩蔽或删除的部分。
```

##### 第五步

压缩器学习如何为不同的推理内容分配重要性，并生成高质量的短思维链。

#### (b) Mixed-ratio SFT 混合比例的监督微调

##### 一句话

教大模型，学会自己生成指定长度的 CoT，

##### 目的
让推理大模型具备固定比例压缩能力，以及初步的自动选比例能力。

##### 翻译

混合比例：其实就是CoT压缩的不同比例

##### 第一步：生成原始CoT
Reasoning LLM：推理大模型，接受数学题目，生成原始的CoT

##### 第二步：压缩原始CoT

第一阶段训练好的 Compressor 对这些长 CoT 进行压缩，产生多种不同长度的版本。
![[截屏2026-10-21 22.32.43.png]]

粉红色的 Token 方块：是Fixed-ratio Data（固定比例数据），用来训练模型遵守压缩比例指令

##### 第三步：根据题目难度选择不同长度CoT

Difficulty Selective Model（难度选择模型）：它负责估计一道数学题更适合使用哪一种推理预算，进而构建 Warm-up Data（预热数据）。

这是为了让模型不只会遵守人工给定的比例，还能初步学会自己选比例。

###### 特殊 Token
```
`<COMP_R>`：固定比例控制
例如输入 `<COMP_40>`，要求模型生成保留比例约为 40% 的推理过程。

`<COMP_POLICY>`：自动比例选择
告诉模型：先自己选一个合适的比例，再按照这个比例进行推理。

区别：`<COMP_40>` 是用户告诉模型“用 40%”；`<COMP_POLICY>` 是让模型自己决定“应该用百分之多少”。
```

###### 火焰🔥与雪花❄️

```
- 火焰：可训练状态，表示该阶段模型参数参与更新。
    
- 雪花：冻结状态，表示模型参数在当前操作中保持固定。
```


#### (c) CHRPO 一种强化学习算法：约束和分层比例策略优化

##### 一句话

教大模型，学会根据题目难度自主选择适合的压缩比例。

##### 目的
用于优化自主策略，经过这个chRPO的优化策略会选择对应的压缩比例，经过SFT训练的模型会遵守这个策略

让模型自动寻找尽可能低、但仍能可靠解题的推理预算。

##### 第一步：Teacher Budget Selection 是什么？

图右上方有五列绿色对勾、红色叉号，对应五个压缩比例：`100%、80%、60%、40%、20%`

作者首先让 SFT 模型分别在这些预算下解题，记录正确与否。

**为什么不是直接选择某次答对的最低比例？（60%）**

```
因为论文要求满足单调正确性（Monotonically Correct），如果在某个压缩比例下答对，那么在比它更宽松的所有预算下也要答对，才将该比例视为可靠的教师预算。这样可以减少偶然答对的情况，提高强化学习数据的可靠性
```

##### 第二步：SFT Model 做什么？

中间的 SFT Model，就是阶段 (b) 训练好的模型。

现在输入数学题和 `<COMP_POLICY>`，模型将先输出一个控制 Token：
例如：`<COMP_40>`，接着生成压缩后的 CoT 和最终答案。

```
论文记录两个值：

- r_c：模型选择的目标压缩比例。
- ^r：模型实际生成的 CoT 保留比例。
注意，选了 40%，不代表生成的 CoT 恰好就是 40%。
```
